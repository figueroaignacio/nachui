An assistant that can read your components still does not know your conventions. It cannot tell from a single file that a `Card` is composed with dot notation, that variants belong in a CVA config declared outside the component, or that colors always go through a token instead of a hex value. It will guess, and the guess will look almost right.

Skills close that gap. Each one is a markdown file you install into your project, describing how a specific part of NachUI is meant to be worked on. The assistant loads the one that matches what you are doing.

## Install

Every skill installs on its own with the [skills](https://skills.sh) CLI:

<div className="my-8">
  <Command command="npx skills add github:figueroaignacio/ui-skills/skills/nachui-usage" />
</div>

The file lands in `.agents/skills/<name>/SKILL.md` inside your project and gets recorded in `skills-lock.json`, so it is committed with everything else and your whole team gets the same instructions.

## Which one you want

Three skills, one job each. Most projects want the first, and the other two once the assistant starts touching the visual side.

- **nachui-usage** is the one to install if you build with NachUI. Import paths, which primitive to reach for, how the pieces compose, what the CLI puts where.
- **nachui-compound-components** teaches the dot notation pattern: `Dialog.Trigger`, `Card.Header`, the shared context behind them, and how to extend a component with a new part without breaking its types.
- **nachui-design** carries the tokens, the spacing and typography rules and the dark mode contract, so an assistant stops inventing hex values and arbitrary sizes.

They are written for people consuming the library. The skills we use to develop NachUI itself live in the same repository but are not listed here, because they assume the monorepo and would only get in the way of your project.

## How they work

Every skill declares in its frontmatter when it should be used:

```markdown
---
name: 'nachui-compound-components'
description: 'Use when building, extending, or consuming compound components.'
---
```

The assistant reads those descriptions, matches them against what you asked for, and pulls in the relevant file before it starts writing. You do not have to name the skill yourself, though nothing stops you from doing it.
