An assistant that can read your components still does not know your conventions. It cannot tell from a single file that a `Card` is composed with dot notation, that variants belong in a CVA config declared outside the component, or that colors always go through a token instead of a hex value. It will guess, and the guess will look almost right.

Skills close that gap. Each one is a markdown file, with reference pages next to it, describing how a specific part of NachUI is worked on. The assistant loads the one that matches what you are doing.

The ones listed here are the skills we actually use to build NachUI. They are read straight from `.agents/skills` in the repository, so this page always shows the set we work with today.

## Install

Every skill installs on its own with the [skills](https://skills.sh) CLI, straight from the NachUI repository:

<div className="my-8">
  <Command command="npx skills add figueroaignacio/nachui --skill nachui-frontend-engineering" />
</div>

The skill lands in `.agents/skills/<name>/` inside your project and gets recorded in `skills-lock.json`, so it is committed with everything else and your whole team gets the same instructions. `npx skills add figueroaignacio/nachui --list` shows the whole set without installing anything.

## Which one you want

Five skills, one job each. Start with **nachui-frontend-engineering**; it sends the assistant to the others when the work calls for them.

- **nachui-frontend-engineering** is the entry point for any UI work: look at the real thing first, build with the library's rules, then review it before calling it done.
- **nachui-component-authoring** takes a component from its API to the catalog: variants, tokens, tests, demos, docs in both locales, the registry and the CLI.
- **nachui-design-tokens** covers the token pipeline, from the DTCG files to every stylesheet, with the contrast checks that keep each theme readable.
- **nachui-design-audit** finds drift against the design rules (radius, spacing, focus, dark mode) with real captures and ranks it before anything changes.
- **nachui-ai-readable-docs** writes docs that a person and an agent read the same way, and explains where each page is served as markdown.

They are written for the NachUI repository, so they name its files (`DESIGN.md`, `packages/ui`, the registry scripts). In your own project they work best as a starting point: install the one you need and point those paths at your own.

## How they work

Every skill declares in its frontmatter when it should be used:

```markdown
---
name: nachui-design-tokens
description: 'Trigger: change a color, radius or shadow token, add or fix a theme preset, contrast, DTCG, Figma variables. The NachUI token pipeline from the DTCG JSON to every stylesheet, with its checks.'
---
```

The `Trigger:` part lists the words that should wake it up, and the sentence after it says what it does. The assistant reads those descriptions, matches them against what you asked for, and pulls in the relevant file before it starts writing. You do not have to name the skill yourself, though nothing stops you from doing it.
