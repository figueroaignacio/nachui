NachUI is an open source design system for React. Add it to your project and start building.

It brings what a product team needs into one place: design tokens, more than 90 components for UI, AI and layout, guidelines for when to use each one, and themes you can make your own. Everything is copied into your repo as plain React and CSS, so you and the agent in your editor read the same source.

## Quick start with AI

Paste this into your AI coding tool and let it handle the setup:

```text
Set up NachUI in this project. Read https://nachui.tech/llms.txt first.
Run `npx nachui init --theme nachui --yes`, then `npx nachui add button card`.
Render a Card with a Button on the home page to check that everything works.
```

## Install

Run `init` once. It asks for a theme, writes the tokens into your stylesheet, creates `nachui.json` and adds the `cn` helper.

<Command command="pnpm dlx nachui init" />

Pass `--theme` to skip the question, for example `--theme nachui` for the look of this site. Try the presets first in [Themes](/themes). If you would rather see every step, the [installation guide](/docs/installation) does the same thing by hand.

## Add your first component

<Command command="pnpm dlx nachui add button" />

The source lands in `src/components/button.tsx`, along with any helper it needs in `src/lib/`. Import it like any other file of yours:

```tsx
import { Button } from '@/components/button';

export function Hero() {
  return <Button>Deploy</Button>;
}
```

## What's in the system

- **[Foundations](/docs/foundations)**: color, type, spacing, radius, elevation, motion and layers, all from one set of tokens.
- **[Components](/docs/elements/ui)**: UI elements with keyboard support, dark mode and right to left built in.
- **[AI elements](/docs/elements/ai)**: the pieces of a chat or an agent run, like messages, reasoning, tools and sources.
- **[Layout](/docs/elements/layout)**: Stack, Grid, Container and the other primitives that place things on a page.
- **[Guidelines](/docs/guidelines)**: when to use each component, and how to write the words around it.
- **[Themes](/themes)**: five presets and a builder to make one yours.

## Built for you and your agent

Nothing is compiled away, so the agent in your editor reads the same React and CSS you do. The docs are published for it too:

- **[llms.txt](/docs/concepts/llms-txt)** indexes every page in the format assistants expect.
- **Raw markdown** comes back when you add `.md` to any docs URL.
- **[The MCP server](/docs/concepts/mcp)** lets an agent search and read the docs on its own.
- **[Skills](/docs/concepts/skills)** teach it the conventions of the system before it writes a line.

Point your assistant at the index once and it stops inventing props that were never there.

## Why copy instead of install

A package hides the code and decides when it changes. Here the source is yours from the first paste: read it, change it, and keep the version that works for you. There is nothing to upgrade unless you want to.

Components depend on five small libraries (`clsx`, `tailwind-merge`, `motion`, `class-variance-authority` and `zod`) and work in any React 19 setup, including Next.js, Vite, TanStack Start and React Router.

## Composed, not configured

Components are built from parts you arrange, like `Card.Header` and `Card.Content`, instead of one tag with a long list of props. You can put anything between the parts, and each part only takes the props it needs. [Compound components](/docs/concepts/compound-components) explains the pattern.

```tsx
<Card>
  <Card.Header>
    <Card.Title>Invite a teammate</Card.Title>
    <Card.Description>They get an email with a join link.</Card.Description>
  </Card.Header>
  <Card.Content>...</Card.Content>
</Card>
```
