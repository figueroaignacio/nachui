Un asistente que puede leer tus componentes igual no conoce tus convenciones. Con un archivo suelto no se entera de que una `Card` se compone con dot notation, de que las variantes van en una config de CVA declarada fuera del componente, o de que los colores siempre pasan por un token en vez de un hex. Va a adivinar, y lo que adivine va a quedar casi bien.

Las skills cubren ese hueco. Cada una es un archivo markdown, con páginas de referencia al lado, que describe cómo se trabaja una parte específica de NachUI. El asistente carga la que corresponde a lo que estás haciendo.

Las que aparecen acá son las skills que usamos de verdad para construir NachUI. Se leen directo de `.agents/skills` en el repositorio, así que esta página siempre muestra el set con el que trabajamos hoy.

## Instalación

Cada skill se instala por separado con el CLI de [skills](https://skills.sh), directo desde el repositorio de NachUI:

<div className="my-8">
  <Command command="npx skills add figueroaignacio/nachui --skill nachui-frontend-engineering" />
</div>

La skill queda en `.agents/skills/<nombre>/` dentro de tu proyecto y se registra en `skills-lock.json`, así que se commitea junto con todo lo demás y todo tu equipo recibe las mismas instrucciones. `npx skills add figueroaignacio/nachui --list` muestra el set completo sin instalar nada.

## Cuál te sirve

Cinco skills, un trabajo cada una. Empezá por **nachui-frontend-engineering**: es la que manda al asistente a las otras cuando el trabajo lo pide.

- **nachui-frontend-engineering** es la entrada para cualquier trabajo de UI: mirar lo real primero, construir con las reglas de la librería y revisarlo antes de darlo por terminado.
- **nachui-component-authoring** lleva un componente desde su API hasta el catálogo: variantes, tokens, tests, demos, documentación en los dos idiomas, el registry y el CLI.
- **nachui-design-tokens** cubre el pipeline de tokens, desde los archivos DTCG hasta cada hoja de estilos, con los chequeos de contraste que mantienen legible cada tema.
- **nachui-design-audit** encuentra lo que se desvía de las reglas de diseño (radios, espaciado, foco, modo oscuro) con capturas reales y lo prioriza antes de tocar nada.
- **nachui-ai-readable-docs** escribe documentación que una persona y un agente leen igual, y explica dónde se sirve cada página como markdown.

Están escritas para el repositorio de NachUI, así que nombran sus archivos (`DESIGN.md`, `packages/ui`, los scripts del registry). En tu proyecto funcionan mejor como punto de partida: instalá la que necesites y apuntá esas rutas a las tuyas.

## Cómo funcionan

Cada skill declara en su frontmatter cuándo debería usarse:

```markdown
---
name: nachui-design-tokens
description: 'Trigger: change a color, radius or shadow token, add or fix a theme preset, contrast, DTCG, Figma variables. The NachUI token pipeline from the DTCG JSON to every stylesheet, with its checks.'
---
```

La parte de `Trigger:` lista las palabras que la tienen que activar, y la oración que sigue dice qué hace. El asistente lee esas descripciones, las compara con lo que le pediste y carga el archivo que corresponde antes de empezar a escribir. No hace falta que nombres la skill vos, aunque nada te impide hacerlo.
