NachUI es un sistema de diseño de código abierto para React. Sumalo a tu proyecto y empezá a construir.

Junta en un solo lugar lo que necesita un equipo de producto: tokens de diseño, más de 90 componentes de UI, IA y layout, guías para saber cuándo usar cada uno y temas que podés hacer tuyos. Todo se copia a tu repo como React y CSS plano, así vos y el agente de tu editor leen el mismo código.

## Empezar con IA

Pegá esto en tu herramienta de IA y dejá que haga la configuración:

```text
Configurá NachUI en este proyecto. Primero leé https://nachui.tech/llms.txt.
Corré `npx nachui init --theme nachui --yes` y después `npx nachui add button card`.
Mostrá una Card con un Button en la página de inicio para comprobar que todo funciona.
```

## Instalar

Corré `init` una vez. Te pregunta qué tema querés, escribe los tokens en tu hoja de estilos, crea `nachui.json` y agrega el helper `cn`.

<Command command="pnpm dlx nachui init" />

Con `--theme` te salteás la pregunta, por ejemplo `--theme nachui` para el look de este sitio. Antes podés probar los presets en [Temas](/themes). Si preferís ver cada paso, la [guía de instalación](/docs/installation) hace lo mismo a mano.

## Sumar tu primer componente

<Command command="pnpm dlx nachui add button" />

El código queda en `src/components/button.tsx`, junto con los helpers que necesite en `src/lib/`. Lo importás como cualquier otro archivo tuyo:

```tsx
import { Button } from '@/components/button';

export function Hero() {
  return <Button>Publicar</Button>;
}
```

## Qué trae el sistema

- **[Fundamentos](/docs/foundations)**: color, tipografía, espaciado, radios, elevación, movimiento y capas, todo desde un único set de tokens.
- **[Componentes](/docs/elements/ui)**: elementos de UI con teclado, modo oscuro y derecha a izquierda incluidos.
- **[Elementos de IA](/docs/elements/ai)**: las piezas de un chat o de la ejecución de un agente, como mensajes, razonamiento, herramientas y fuentes.
- **[Layout](/docs/elements/layout)**: Stack, Grid, Container y las demás primitivas que ubican las cosas en la página.
- **[Guías](/docs/guidelines)**: cuándo usar cada componente y cómo escribir el texto que lo acompaña.
- **[Temas](/themes)**: cinco presets y un builder para hacer uno tuyo.

## Hecho para vos y tu agente

Nada se compila ni se esconde, así que el agente de tu editor lee el mismo React y el mismo CSS que vos. La documentación también se publica para él:

- **[llms.txt](/docs/concepts/llms-txt)** indexa cada página en el formato que esperan los asistentes.
- **El markdown crudo** aparece si le agregás `.md` a cualquier URL de la documentación.
- **[El servidor MCP](/docs/concepts/mcp)** deja que un agente busque y lea la documentación por su cuenta.
- **[Las skills](/docs/concepts/skills)** le enseñan las convenciones del sistema antes de que escriba una línea.

Apuntá tu asistente al índice una vez y deja de inventar props que nunca existieron.

## Por qué copiar en lugar de instalar

Un paquete esconde el código y decide cuándo cambia. Acá el código es tuyo desde que lo pegás: lo leés, lo cambiás y te quedás con la versión que te sirve. No hay nada que actualizar salvo que quieras.

Los componentes dependen de cinco librerías chicas (`clsx`, `tailwind-merge`, `motion`, `class-variance-authority` y `zod`) y funcionan en cualquier proyecto con React 19, como Next.js, Vite, TanStack Start o React Router.

## Compuesto, no configurado

Los componentes se arman con partes que ordenás vos, como `Card.Header` y `Card.Content`, en lugar de una sola etiqueta con una lista larga de props. Podés poner lo que quieras entre las partes, y cada una recibe solo las props que necesita. [Compound components](/docs/concepts/compound-components) explica el patrón.

```tsx
<Card>
  <Card.Header>
    <Card.Title>Invitar a alguien del equipo</Card.Title>
    <Card.Description>Le llega un mail con un link para sumarse.</Card.Description>
  </Card.Header>
  <Card.Content>...</Card.Content>
</Card>
```
